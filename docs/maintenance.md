# Maintenance

How to run and test: [README](../README.md#run-and-test). Exact formats and settings (folder order, `PORT`, `OWNWORDS_IDLE_MS`, test hooks): [CONTRACT.md](../CONTRACT.md). This file covers releases, changes, troubleshooting and where things live.

## Before you change code

- Run `node --test` and `sh launcher/test.sh` first, so you know the baseline. Both use temp folders, a temp home and free ports; they never touch your real folder or `~/.ownwords-lite`.
- Fix a bug with a failing test first, then the code.
- Do not edit `public/` while a live server is serving it to an open page. Use a copy or another port (`PORT=4747 node server.js <temp folder>`).
- Reload the tab before you judge a page bug. A hash-only navigation keeps the old page code. A screenshot taken mid-animation can look like a bug: read the page state (DOM) first.

## Release

A release is a zip of the repo. From a clean `main`:

```
node --test && sh launcher/test.sh
git archive --format=zip --prefix=ownwords-lite/ -o ../ownwords-lite-<version>.zip HEAD
```

`git archive` leaves out `.git` and untracked files. Bump `version` in `package.json` first. Never put a built `Open Ownwords.app` in the zip: it is built on each user's Mac by `INSTALL.md`.

## Change the agent instructions

Edit `templates/OWNWORDS.md`. Keep its first line (`<!-- Generated by Ownwords ...`): the server only rewrites files that start with it. `{{DIR}}` and `{{APP}}` are filled in on start. Restart the server and check `<folder>/OWNWORDS.md`. A user's own `OWNWORDS.md` without that first line is never overwritten.

The skill pointer (`skill/SKILL.md`) should stay a pointer. Change it only if the way to find `OWNWORDS.md` changes, and tell users to copy it again (re-run `INSTALL.md`).

## Known risks

- **Sync folders** (iCloud, OneDrive, Dropbox). They can create conflict copies, keep files as placeholders, or lock a file for a moment. Not tested. A conflict copy shows up as a new piece.
- **Other pages on this machine.** The Host and content-type checks stop simple cross-site requests, but the API has no token. A hostile local program can always read your files anyway.
- **Hidden tabs.** Browsers slow timers in background tabs. The 10-minute idle stop leaves room; if a hidden tab still lets the server stop, the page shows "Ownwords stopped" and recovers when restarted.
- **Port 4646 is fixed in practice.** `PORT` works for the server and the launcher, but `OWNWORDS.md`, the skill and an installed app window all assume 4646. Use other ports only for testing.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| Page says "Ownwords stopped" | The server stopped (idle 10 minutes, or it was closed). Double-click `Open Ownwords`, or ask the agent; it starts the server every turn. Unsaved selections and marks are kept and sent when it is back. |
| Page does not load at all | The server is not running. Start it: `node <app>/server.js`, or the launcher. Check `curl -s http://127.0.0.1:4646/api/info`. |
| Server says port 4646 is used by another program | Something else holds the port. Find it with `lsof -nP -iTCP:4646 -sTCP:LISTEN` and stop it, or set `PORT` for a test run. The server never stops programs that are not Ownwords. |
| Server says "could not stop the other Ownwords server" | An older Ownwords on the port did not answer the stop request. Find its pid with `curl -s http://127.0.0.1:4646/api/info` (or `lsof` above), stop it, start again. |
| Double-click on `Open Ownwords` shows "could not start" | The dialog's second line says why. "needs Node 22" means Node is missing or old, or installed somewhere the launcher does not look: install from nodejs.org or Homebrew. A `Log:` path means the server failed: read `<folder>/.ownwords/server.log`. |
| Launcher icon is blank, or macOS says it cannot verify the developer | The app was copied from another machine. Rebuild it: `sh <app>/launcher/build.sh <app> <folder>`. Never download a built `.app`. |
| macOS asks to let "Open Ownwords" (or your terminal) access the Desktop | Expected the first time, because the folder is on the Desktop. Click Allow. If it was denied: System Settings, Privacy and Security, Files and Folders, turn it on. |
| `OWNWORDS.md` has old paths after the app folder moved | Run `node <new app>/server.js` once. It rewrites `OWNWORDS.md` and line 2 of `~/.ownwords-lite`. Rebuild the launcher too. |
| Server says "Kept your OWNWORDS.md; it may be stale" | Your folder has an `OWNWORDS.md` that the server did not write. Rename it if it is a piece, then restart: the server writes a fresh one. |
| No Install item in Chrome's menu | The item's place and name change between Chrome versions (look under "Cast, save and share"), and some managed profiles hide it. Reload the page while the server runs and look again. Not confirmed on every version for `127.0.0.1`. The launcher's app window works without installing. |
| Windows: a save fails with EPERM or EBUSY | Another program (antivirus, OneDrive, an editor) held the file during the rename. Try again. Keep the folder outside OneDrive if it keeps happening. |
| An agent's edits made while the server was stopped show as one timeline row | Expected. Snapshots are taken when the server sees a change; several edits while it was down become one. |
| Agent edit does not show on the page | Wait a second (the page polls). If a version group vanished into the "stale" list, the text changed under it: ask the agent to rebuild the group. |

## Where things live

| What | Where |
|---|---|
| Your pieces | `<folder>/*.md` (default `~/Desktop/Ownwords`) |
| Drafts, marks, history | `<folder>/.ownwords/<id>/` |
| Server log (when started by the launcher) | `<folder>/.ownwords/server.log` |
| Agent rules | `<folder>/OWNWORDS.md` (generated) |
| Launcher | `<folder>/Open Ownwords.app` (macOS, built locally) |
| Folder and app paths | `~/.ownwords-lite` (line 1 folder, line 2 app) |
| Skill pointer | `~/.claude/skills/polish/SKILL.md` (Claude Code), `~/.agents/skills/polish/SKILL.md` (Codex) |
| App code | wherever the repo was unzipped |
